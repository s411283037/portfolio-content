# 個人作品集網站｜設計與互動規格

版本：1.0｜日期：2026-11-16｜階段：設計規格，尚未開發或部署

## 1. 文件用途與決策狀態

本文件與根目錄 AGENTS.md 搭配使用：AGENTS.md 規範內容真實性、資料管理與維護流程；本文件規範網站版面、視覺及互動。AI 建立或修改頁面前須同時閱讀兩份文件。內容更新沿用既有元件，不自行重新設計全站。

使用者已確認：以認識個人為閱讀起點；採滾動式首頁並具有點選互動；首頁暫不放個人照片；整體簡約大氣、有線條感；避免卡通、可愛化與橘色；配色選擇 B「深茄紫 × 灰藕紫 × 淡米白」。

以下頁面順序、尺寸、元件與動效為依上述方向整理的第一版實作預設，可在預覽後調整，並非全部經逐項確認。實際個人文案、案例、履歷、聯絡方式與素材尚待整理；不得直接採用示意圖中的虛構內容。技術框架、GitHub 儲存庫及部署平台尚未選定。

## 2. 網站目的與閱讀體驗

主要讀者為 HR 與用人主管。網站作為履歷延伸，讓讀者先理解「我是誰、關注什麼、如何做事」，再透過案例判斷個人貢獻、執行能力、成果與職位適配性。

採兩層閱讀：首頁提供完整但精簡的個人輪廓；獨立案例頁提供決策、過程、證據與反思。個人特質需透過行動呈現，不單靠形容詞或技能評分。

## 3. 頁面架構與導覽

| 頁面 | 建議路徑 | 功能 |
| --- | --- | --- |
| 滾動式首頁 | / | 個人開場、關於我、學經歷、精選案例、技能與證照、聯絡 |
| 案例頁 | /projects/<id>/ | 可直接分享的完整案例 |
| 全部專案頁 | /projects/ | 案例增加後才啟用，第一版不強制建立 |
| 找不到頁面 | /404.html | 清楚說明並提供返回首頁入口 |

桌面導覽為「關於我／學經歷／專案／技能／聯絡」，各自對應首頁 #about、#experience、#projects、#skills、#contact。姓名或文字識別連回首頁頂部。導覽使用真實連結，允許複製錨點與瀏覽器上一頁操作。

案例頁導覽點選首頁區塊時使用完整首頁錨點；不得跳到案例頁內不存在的區塊。部署於 GitHub Pages 子路徑時，所有連結與素材須支援實際 base path，不能假設永遠部署於網域根目錄。

## 4. 視覺系統

### 4.1 色彩

| Token | 色碼 | 用途 |
| --- | --- | --- |
| background | #F5F1F0 | 全站主要背景，淡米白 |
| primary | #493347 | 主要標題、實心按鈕、重點線條、頁尾，深茄紫 |
| accent | #B5A0AE | 幾何色塊、裝飾、局部底色，灰藕紫 |
| surface | #E9E0E5 | 柔和區塊背景，第一版輔助色 |
| text | #29252A | 主要內文 |
| text-secondary | #645963 | 次要說明，實作時檢查對比 |
| border | #CBBFC8 | 非必要裝飾分隔線，不作唯一互動邊界 |
| on-primary | #F5F1F0 | 深色底上的文字 |

淡色背景占主要面積，深茄紫集中於標題、操作入口與頁尾；灰藕紫不鋪滿全站。不添加橘色、粉彩糖果色、大面積漸層、金屬金或其他未定義的強調色。

一般文字對比至少 4.5:1，大字至少 3:1；可操作元件的必要邊界與狀態標示至少 3:1。灰藕紫不直接用於米白底的小字；其上放深色文字。實作需量測實際組合，不能僅憑色票宣稱合格。

### 4.2 字體與文字

- 中文內文優先使用 Noto Sans TC，搭配系統無襯線字體備援。
- 姓名與主要展示標題可使用 Noto Serif TC；英文展示字採相容襯線字體，營造編輯式氣質。以實際中文畫面驗證，不能只依英文示意圖判斷。
- 最多兩套字體家族與必要字重；優先子集化或可控載入，避免載入完整多字重中文字型。
- 內容以繁體中文為主；區塊可附 About、Experience、Projects 等英文小標，不以英文取代重要資訊。
- 桌面姓名約 64–96px，手機約 40–56px，依姓名長度流動縮放；區塊主標約 32–48px，手機約 28–36px。
- 內文 16–18px，行高約 1.7–1.85；輔助標籤不小於 14px。文字不固定高度，不截斷必要內容。

### 4.3 網格、留白與線條

- 桌面內容最大寬度 1200px，左右留白約 48–64px；手機左右留白 20–24px。
- 以 8px 為主要間距單位；桌面區塊上下約 80–112px，手機約 48–64px。
- 內文閱讀區最大寬約 720px；大圖與頁首可使用較寬網格。
- 使用 1px 細線、少量垂直分隔線、章節編號與精準對齊建立結構。不要每個段落都畫框或加線。
- 直角為主，功能元件可使用 0–4px 小圓角；避免膠囊按鈕、厚陰影、玻璃擬態與大量浮動卡片。
- 幾何弧線與矩形僅作裝飾，不遮擋文字、不承載必要資訊、不搶過姓名與內容。

## 5. 首頁區塊規格

### 5.1 個人開場 Hero

首屏以姓名與個人定位為主視覺，不放照片、不放人物插圖，也不預留照片空框。桌面採不對稱文字構圖：左側為姓名、一句定位及簡介，右側為留白、細線及少量灰藕紫幾何色塊。手機以文字為主，減少裝飾。

內容依序為公開姓名、定位、約 2–3 行簡介及操作入口。主按鈕「認識我」連到 #about，次按鈕「查看專案」連到 #projects。履歷入口放導覽或後續區塊，不增加第三個同等醒目的主按鈕。

首屏不強制滿版，不以過大留白阻止讀者發現後續內容。姓名、標語及定位須依使用者資料撰寫；未確認前只存在於內部草稿。

### 5.2 關於我 About

以簡短敘事呈現背景、關注方向及工作方式。桌面左側放章節編號與標題，右側放 2–3 段內容；手機依序單欄。可採 surface 底色與垂直細線形成層次。

如呈現個人特質，最多先選 3 項，各附具體行動或案例連結；資料不足時不硬湊數量。不把履歷逐字搬入本區，也不重複 Hero 簡介。

### 5.3 學經歷 Experience

學歷與培訓、工作與相關經歷分組呈現，不能將不同性質混成難以閱讀的一條長時間軸。以細直線及小節點連接各筆紀錄，日期與角色清楚對齊；排列順序沿用內容資料設定。

每筆預設顯示期間、機構、角色與一行重點。較長內容可點「展開內容」查看具體職責或成果，展開後文字改為「收合內容」。短紀錄直接完整顯示，不為互動而折疊。若有相關案例，提供明確連結。

### 5.4 精選專案 Projects

第一版目標呈現 2–3 個資料足夠的案例；數量不足時呈現實際可用案例，不新增空白卡片。桌面兩欄，手機單欄。卡片以細線與排版分區，保持足夠文字空間。

每張包含：案例名稱、簡短問題或目標、個人角色、已確認的成果摘要、類型標籤，以及「閱讀案例」連結。圖片選用，比例預設 16:10；沒有可公開圖片時採文字式卡片，不以虛構介面冒充成果。

卡片主連結採原生連結並保留可見焦點；避免巢狀按鈕或多個重複導向同頁的焦點。滑入時可改變線條、文字或箭頭，資訊不依賴 hover 才出現。

案例較多時可加入分類篩選，第一版不強制。若啟用，需有「全部」、目前選取狀態、鍵盤操作與無結果提示；不改變資料本身的發布狀態。

### 5.5 技能與證照 Skills & Credentials

技能按實際用途分類，例如專案方法、AI 與工具、語言；分類名稱以資料為準。每項簡述使用情境，適用時連到案例。不用星等、百分比或未經定義的熟練度長條。

證照採簡潔列表：名稱、發證單位、取得時間與可用驗證連結。證書圖片可點開檢視；沒有驗證網址就不顯示驗證按鈕。技能與證照以同一大區塊下的兩個小節呈現，避免首頁區塊過碎。

### 5.6 聯絡 Contact 與頁尾

以深茄紫底搭配淡米白文字收尾。提供簡短聯絡邀請、已確認公開的 Email，以及有實際網址的其他入口。Email 使用 mailto 連結；如提供複製功能，需有成功或失敗回饋與原生連結備援。

履歷檔案已存在才提供「下載履歷」，並標示 PDF；瀏覽器無法直接下載時至少可開啟。缺少附件時隱藏入口，不放無效按鈕。第一版不建立聯絡表單或後端服務。

## 6. 案例內頁

頁首提供返回專案區入口、案例名稱、摘要、期間、角色、團隊規模與專案階段；只顯示已有資訊。依 AGENTS.md 的內容格式呈現背景與目標、個人貢獻、思考與執行、成果與證據、反思與學習。

長案例可加桌面側邊章節目錄；手機改為可展開的目錄。必要內容直接可讀，不把核心貢獻與成果全部藏入折疊區。段落標題產生穩定錨點。

成果數字旁須交代必要語境；不要把測試準確率當商業成效。圖片緊鄰相關說明並附圖說。頁尾可連往其他已發布案例及聯絡區，不建立不存在的「下一篇」。

從首頁進入案例再返回時，盡可能保留原本捲動位置。直接進入案例網址或重新整理時仍可正常顯示。

## 7. 互動與動效

| 互動 | 行為與限制 |
| --- | --- |
| 固定導覽 | 捲動時保持可用；以文字或底線標示當前區塊；錨點預留導覽高度，避免標題被遮擋 |
| 平滑捲動 | 僅用於頁內導覽；保留正常滾輪、觸控與瀏覽器歷史，不攔截捲動 |
| 區塊進場 | 可採 250–400ms 淡入與最多 12px 位移，每區一次；內容預設可見，腳本失敗仍能閱讀 |
| 按鈕與連結 | 約 150–200ms 色彩或底線變化；hover 與鍵盤 focus 都清楚 |
| 經歷展開 | 原生 details/summary 或等效可及按鈕，具展開狀態；不改變其他紀錄內容 |
| 圖片放大 | 開啟對話框；可按關閉、Escape 或背景關閉；焦點留在框內，關閉回到原觸發點；大圖可捲動閱讀 |
| 手機選單 | 可展開／收合，有文字標籤與狀態；選取後關閉，不遮住目標內容；若採覆蓋式對話框需管理焦點 |

遵守 prefers-reduced-motion：停用位移、進場與平滑捲動，保留即時功能。禁止自動播放影音、跑馬燈、游標追蹤特效、強制逐屏吸附與過場等待。

## 8. 響應式與可及性

- 初始斷點：小於 768px 為手機，768–1023px 為中型畫面，1024px 以上為桌面；依實際內容調整，不以裝置名稱硬限制。
- 小畫面單欄呈現，時間軸日期移到內容上方，卡片與按鈕不超出容器；裝飾可減少或隱藏。
- 至少驗證 360、768、1280、1440px 寬度；200% 縮放可讀，長網址及中文標題不造成整頁水平溢出。
- 觸控操作區目標至少 44×44px；所有控制可使用鍵盤，焦點標示不可移除。
- 提供跳至主要內容連結，使用 header、nav、main、section、footer 語意結構；每頁一個 h1，後續標題有邏輯層級。
- 重要文字不得只存在圖片、動畫或顏色中。證明圖片提供有意義的替代文字，純裝飾設為忽略。

## 9. 素材、內容與載入

- 使用 AGENTS.md 定義的 content/ 資料來源與 public/assets/ 素材位置，不在不同頁面重複手寫姓名、角色或成果數據。
- 精選與排序由 featured、order 控制；新增內容自動沿用共用元件，不要求 AI 複製整頁 HTML。
- status: draft 不輸出到正式網站。已發布紀錄缺少選用資訊時省略該列；缺少關鍵事實時依規則留草稿，不編造填滿。
- 圖片使用適合尺寸與格式，設定寬高以減少版面跳動；非首屏圖片延遲載入。證書與流程圖以清晰可讀為優先，不裁掉重要內容。
- 字體提供備援，不等待字體或動畫完成才顯示文字。主要內容與導覽採漸進增強，即使互動腳本失敗仍可讀取。
- 不把完整原始教材、企業文件或未獲准資料隨網站部署。

## 10. 技術與交付邊界

第一版採靜態網站方向，不需要登入、資料庫、管理後台或 AI 聊天功能。內容透過 Codex 修改專案檔案，GitHub 保存版本，部署平台負責發布。

正式開發時選定支援 Markdown／YAML 與靜態輸出的方式，將實際啟動、建置、檢查、base path 與部署步驟寫入 README.md。不得將預定指令當作已驗證指令。

每頁需有適當頁面標題、簡介與語言設定。社群分享圖選用且須真實存在；公開網址確認後再設定正式網址資訊。任何部署授權沿用 AGENTS.md，本文件不另行授權發布。

## 11. 設計驗收清單

- [ ] 無照片 Hero，以姓名與個人定位建立視覺重點，沒有空白照片框。
- [ ] 使用 B 配色與細線語言，繁體中文排版完整，未混入示意圖虛構文案。
- [ ] 首頁閱讀順序能先認識個人，再深入經歷與案例。
- [ ] 導覽、展開、案例連結、圖片檢視與履歷入口皆有實際作用。
- [ ] 案例可直接開啟與重新整理；從子路徑部署仍可載入頁面與素材。
- [ ] 對比、鍵盤焦點、手機選單與圖片對話框經實際檢查。
- [ ] 手機、桌面及減少動畫設定下均可閱讀操作。
- [ ] 沒有空卡片、假數據、失效按鈕或公開草稿。
- [ ] 內容增加後仍沿用同一套元件，無須重新設計版面。
- [ ] 修改、預覽、推送與正式發布的狀態分別如實回報。

## 12. 下一階段需要補齊

先整理公開姓名、個人定位與介紹，選出第一版案例及可公開證據，提供履歷與聯絡入口；再依本文件製作首頁與案例頁預覽。字體搭配、區塊比例與輔助色可在真實中文內容的預覽中微調，調整結果同步寫回本文件。

未來若增加照片，只修改 Hero 的可選素材配置；不得因沒有照片而影響網站基本使用。雙語、專案篩選與其他功能按實際需求另行擴充，不提前增加使用負擔。
